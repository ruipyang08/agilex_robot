### M1-6 断电后位置基准丢失（2026-09-29 实测，重要）

**现象**：在 lift 高度非 0 时整机电断电，重启后节点把高度当成 0。

重启后 `rostopic echo -n1 /lifter_1/LiftMotorStatePub` 抓到的值：

| 字段 | 值 | 含义 |
|---|---|---|
| `backPos` | **-206** | 驱动 0xE0 位置寄存器原值，单位脉冲（1mm=12500 脉冲） |
| `backHeight` | **0** | = round(-206/12500)，**是驱动器算的，不是软件换算的** |
| `initState` | **True** | ⚠ 纯软件标志（`mode != 1` 即 True），**不代表坐标基准还在** |
| `downLimit` | **False** | **关键证据**：下限位开关没被压到 → 柱子物理上不在最低点 |
| `upLimit` | **False** | 上下限位都没触发 → 柱子停在行程中间某处 |
| `stateBit` | 129 (0x81) | runState + `externalCtrlMode`，无过流/过压/欠压/编码器故障 |

**结论**：830ABS 的位置基准靠「下降压下限位 + 清零（0x4B/0x4C）」建立，**整机断电重启后丢失**，
驱动器多圈位置回到 ≈0。这推翻了原先 `AGENTS.md` 里「绝对值编码器，`initState` 会保留，
正常情况下无需重新初始化」的说法。驱动器自己的 README 才是对的：
`initMode` 1 = 上电自动初始化；`MotorClearPosZero()` 注释「这个指令**失电失效**，
每次上电初始化都会执行」。

**恢复**：`lift init`（mode=1）→ 下降到下限位 → 3× 清多圈+清零 → 走 `initPos`(0)。
⚠ 真实运动，约 1 分钟（`initSpd: -500` → 约 6.7mm/s），会下降掉当前未知高度。

**上电校验与门禁**：见 `decisions.md` D20。节点现在把可信高度落盘
`~/.ros/lift_frame_m1.json`，上电时比对，差 >20mm 判为未标定并拒绝位置指令。

**未测项**：只测了「整机电断电 overnight」这一种情况。「只重启电脑、驱动器没断电」
（位置应该还在）以及「短时断电（电池/电容可能还撑得住）」都没测过。

## M5. 升降柱碰撞区干跑验证

**用途**：在不改 URDF/SRDF 的前提下，验证"把升降柱当碰撞体"是否必要、以及需要几条 SRDF 豁免。为 `ranger_xarm6_lifting_2431.xacro` 的 `lift_inner_link` 落地做前置确认。

**方法**（2026-09-28，均在运行中的 move_group 上做，零文件改动）

把柱体做成 `AttachedCollisionObject`（212 × 212 × 650 mm，挂 `link_base`，`touch_links=[link_base, box_link, base_link]`）**内嵌进 `check_state_validity` 请求的 `RobotState`**，对采样状态做有效性与接触对检查。

> ⚠ **踩过的两个坑（下次直接用结论）**
> 1. `check_state_validity` 只有在**空 `robot_state`**（用场景当前态）或**把附着物体内嵌进请求**时才计入物体；只给显式关节值会把物体忽略——第一轮据此得到"0 拦截"的错误结论
> 2. `AttachedCollisionObject` 的 `REMOVE` 语义是"**脱附并放回世界**"，不是删除；必须再发一条世界物体的 `CollisionObject REMOVE` 才能清干净，否则残留物体会堵住整个场景

**结果**

| 项 | 结果 |
|---|---|
| 阳性对照 | 盒子移入肩部 → 检出 `link1/link2/link3/link4` 接触 ✔（装置有效） |
| 豁免对照 | 小盒只埋进臂法兰 → `valid=True` ✔（`touch_links` 生效） |
| 采样规模 | 597 个配置（297 结构网格 + 300 随机），基线自碰撞已剔除 |
| **柱体 212mm** | **24 个配置真撞柱**（撞点：`link4/link5`、夹爪基座、`left_crank`、`left_distal_phalanx`）→ **机械臂确实能够到柱体** |
| 豁免充分性 | 无任何配置"仅因撞箱体/底盘/法兰"被误拦 → **3 条豁免（box_link / base_link / link_base）足够** |
| 膨胀探测 | 截面 300→17 拦、400→20 拦、500→25 拦（网格子集）→ 真几何检测，有梯度、非开关式误报 |

**结论**：柱体碰撞区识别正确、确有必要；将来若要把它并入 MoveIt 碰撞模型，按上表 3 条豁免即可，无需更多。

## M7. 绿盖抓取点（试管架摆在机器人台面上）

**用途**：用 `plane_target` 红点链路抓绿盖的落点与夹爪参数。在 `tube_grasp` 自动链路通过准入之前，这是真机上唯一的抓取通路。

**条件**

| 项 | 记录 |
|---|---|
| 日期 / 操作人 | 2026-10-22 / 用户 + Agent |
| 启动命令 | `roslaunch agx_bringup hardware.launch start_base:=false enable_tube_grasp:=true`（29 节点） |
| 末端 | `tcp_link`（闭合指尖下沿中点，M2 的 0.170 m） |
| 坐标系 | `deck_top`（基准面 z=0；对应 base_link (−0.190, 0, 0.347)） |

| 起始位姿 | SRDF `initial`，tcp = deck_top (0.281, 0.010, 0.440) |

**落点（红点 = 抓取点）**

| 项 | deck_top (m) | base_link (m) |
|---|---:|---:|
| 红点 x / y / z | 0.259 / −0.005 / 0.100 | 0.069 / −0.005 / 0.447 |
| 抓取时 `tcp_link` 实测 | 0.259 / −0.005 / 0.100 | 0.069 / −0.005 / 0.447 |

`~plane_z` 用默认 **0.100** 即可，不需要改；红点矩形 x∈[0.106, 0.565]、y∈[−0.25, 0.25] 够用。

**夹爪读数**

| 阶段 | `position` | `grip_state` |
|---|---:|---:|
| 张开待抓 | 1000 | 1 |
| 夹住绿盖（目标 0） | **268** | **2** |
| 空夹到底（第一次瞄偏时） | 0 | 3 |
| 抬起 340 mm 回 initial 后 | 267 | 2 |

**瞄准过程**

1. 第一次瞄 deck_top (0.274, −0.005)：闭合到 0、`grip_state=3` → **空夹**。用户目视：高度齐平，前后偏 1~2 cm 且偏前（+x）
2. 红点后移 15 mm 到 (0.259, −0.005) 重抓：停在 **268**、`grip_state=2` → 夹住
3. `/plane_target/home` 抬起 340 mm：position 268→267（0.1 mm），状态仍为 2 → **抓取牢固**
4. 同一落点张开到 1000 放回原位，再 home

**相机 / 检测侧的限制（这几条决定了不能再靠视觉闭环）**

| 现象 | 实测 |
|---|---|
| 绿盖颜色 | HSV **H=88, S=230, V=170** |
| 配置窗口 | `target_hsv_lower/upper` = [40,80]/[80,255]/[50,255] → **H 上限 80 会漏掉这支盖**，实测严格阈值下绿色像素为 0 |
| 深度 | 盖面反光，`/cam1/depth/image_rect_raw` 在盖上大量 NaN，**不能用深度测盖高** |
| 腕装相机 | 抓取位离指尖仅 ~0.11 m，视野不可用；只能靠像素反投影 + 人工目视校核 |
| 官方检测服务 | 升降 `stopFlag=True`（静止）时 `/detect_tube_cap` 直接返回 status=4 `lift feedback reports a fault`，当前不可用 |

**有效判据**（可复用）：夹爪 `position` 停在 250~500 且 `grip_state=2` 才算夹住；停在 0 / `grip_state=3` 一定是空夹。M4 的语义表已按本条实测填写。
