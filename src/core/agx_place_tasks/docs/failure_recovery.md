# 取放任务的失败与恢复

本文记录机载蓝盒取放（`pick_from_onboard` / `place_test_tube`，以及独立脚本
`green_tube_cycle.py`）在实机上已经遇到和可以预见的失败，以及目前可用的观测信号与恢复动作。
它是策略设计的输入，不是已经实现的机制——除特别说明外，本文列出的恢复步骤目前都需要人工执行。

## 1. 可用的观测信号

| 信号 | 来源 | 能说明什么 | 可信度 |
|---|---|---|---|
| 夹爪实测位置 | `/gripper/states` 的 `position` | 两指停在多宽：空夹爪会走到指令值，夹住物件会停得更高 | 高（本次判据的基础） |
| 夹爪状态位 | 同上的 `grip_state` | 0 运动中 / 1 到位 / 2 夹住 / 3 掉落 | 低（临界值附近反复跳变，实测不可依赖） |
| 机械臂状态 | `/xarm/xarm_states` 的 `mode` / `state` / `err` | 是否有故障、是否使能 | 高 |
| 规划结果 | MoveIt `plan()` / `go()` 返回值 | 是否有可行轨迹 | 高 |
| 直线执行比例 | `compute_cartesian_path` 的 `fraction` | 直线段是否走得完整（<0.999 表示被限位或碰撞挡住） | 高 |
| 末端实际位姿 | TF `link_base_lift0` → `tcp_link` | 臂是否真的到了目标点 | 高 |
| 相机图像 | `/cam1/color/image_raw` | 某个孔位是否还有管子（需要稳定光照与色窗） | 中（软盖会被压缩、颜色接近） |

判据参考值（2026-11-11 实机，点位 2）：

```
闭合指令 150  ->  空夹爪 150（余量 0）   夹住绿盖 270（余量 +120）
判定：实测 - 指令 >= 60 才算夹到
```

## 2. 移动阶段

| 编号 | 情况 | 现象 | 现有行为 | 恢复动作 |
|---|---|---|---|---|
| M1 | 目标不可达 / 自碰撞 | `plan()` 失败或 `go()` 返回 `TIMED_OUT`，臂不动 | 中止，臂留在原位 | 换路点或回 `initial`；不要原地重试同一目标 |
| M2 | 直线下降走不完整 | `fraction < 0.999` | 拒绝执行，臂停在接近点 | 降低接近高度（后排点位用 `approach_z_m: -0.020` 就是这个原因） |
| M3 | 执行中断连 | `CONTROL_FAILED`，臂停在轨迹中途 | 中止，臂带故障停住 | 先清故障并确认位置，再回 `initial` |
| M4 | 到点位置有偏差 | 无自动检测 | 无 | 拍照复核或人工目视 |

## 3. 抓取阶段

| 编号 | 情况 | 现象 | 现有行为 | 恢复动作 |
|---|---|---|---|---|
| G1 | 夹爪无反馈 / 未初始化 | `/gripper/states` 无数据或 `is_initialized=false` | 无法判定，动作超时 | 先初始化夹爪，不要盲抓 |
| G2 | 夹爪卡死 | 位置长时间不变但指令未到达，力持续 | 超时 | 立即张开并抬臂，避免压坏管子 |
| G3 | 判空但实际夹住（假阴性） | 实测位置与指令差很小，但管子确实被带起 | custody 缺失，后续放置被拒 | 用抬升后的复核或人工确认；必要时补一次同点重试 |
| G4 | 判夹到但实际为空（假阳性） | 实测位置高出指令，但孔里本就没管子（或夹到异物） | 会写入 custody | 退回后确认该格状态，必要时就地释放 |
| G5 | 夹到邻管 / 夹到盒壁 | 实测位置显著高于盖径对应值（例如 446 对应 44.6 mm） | 判为夹到 | 视为抓取失败：原位释放、抬臂、重新定位 |
| G6 | 只夹住盖边缘 | 抬升过程中滑脱 | 掉落时 `grip_state` 可能报 3 | 抬升前小幅上提再复核，或降低抓取高度 |

## 4. 搬运与放置阶段

| 编号 | 情况 | 现象 | 现有行为 | 恢复动作 |
|---|---|---|---|---|
| P1 | 抬升后掉落 | 夹爪张开值异常、管子不在手中 | 无检测 | 记录该点状态为“未知”，重新观察盒内 |
| P2 | 放置没对准孔口 | 管子横在盒面，挡住相邻孔位 | 无检测 | 停止自动流程，人工扶正 |
| P3 | 放得太浅 | 管子倾斜，下次抓取高度失效 | 无检测 | 人工检查后重测该点位 |
| P4 | 张开后管子黏在指尖 | 抬臂时把管子带走 | 无检测 | 抬臂后二次张开 |

## 5. 系统级

| 编号 | 情况 | 现象 | 恢复动作 |
|---|---|---|---|
| S1 | CAN 掉线 | 底盘/升降无响应 | 重新拉起 `can0`（免密规则） |
| S2 | 到机械臂的路由丢失 | `ping` 失败，驱动失联 | 重新添加 /32 路由，重启驱动栈 |
| S3 | ROS master 或节点被杀 | `rosnode list` 为空 | 重启整套栈，重新确认臂状态 |
| S4 | 断电 / 急停 | 全部状态丢失 | 重新初始化（升降、夹爪），并人工确认管子位置 |
| S5 | 升降被移动 | 所有点位 z 失效 | 确认升降回到 0，否则重新标定 |

## 6. 现在能自动做到哪一步

| 能力 | 状态 |
|---|---|
| 单段动作超时中止 | 有（`stop_requested` 逐步检查） |
| 直线段不可达时拒绝执行 | 有（`fraction < 0.999`） |
| 抓取判定（含余量） | 有（实测 - 指令 ≥ 60） |
| 失败后自动退回接近点 | 有（每个动作段的 `retreat`） |
| 跨任务恢复（清故障、回安全位、重新定位） | **无**，目前为人工步骤 |
| 失败后的“管子在哪”判定 | **无** |
| 断电/中断后的状态重建 | **无** |

## 7. 设计策略时需要先定的四件事

1. **自愈边界**：哪些故障自动恢复（清故障、回 `initial`、同点重试一次），哪些必须停机等人。
2. **“管子在哪”的判据**：目前只有夹爪读数。可以考虑把 custody 从“有/无”扩成
   “夹爪持有 / 在盒内某格 / 未知”三态，并在抓取前后各确认一次目标格。
3. **记录粒度**：每次尝试都要留下 `点位 / 指令 / 实测 / 判定 / 结果`，否则事后无法分析窗口漂移。
4. **安全优先级**：宁可停在安全高度等人，也不要为了完成任务继续下探。

| 场景 | 指令 | 实测 | 余量 | 判定 |

| 有料（点位 2，绿管） | 150 | 270 | +120 | 夹到 |
| 空料（同点位，管已抽出） | 150 | 150 | 0 | 空 |
| 夹爪全程行程（空夹） | 750 → 150 | — | — | 1.70 s |
| 夹爪张开行程 | 150 → 1000 | — | — | 2.04 s |
